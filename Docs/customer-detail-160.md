# 顧客詳細の整合性・導線の受入（#160）

## 範囲と修正（2026-11-24）

調査基準mainは`35d19d7`。既存のREADME変更と未追跡のRF文書2件を保持し、`fix/customer-detail-160`で実装した。タブ化（#225）・全画面UI統一（#226）は対象外。

- 詳細のRF取得を一覧と共通の`Customers::CurrentRfQuery`へ統一。適用履歴なし・未計算・対象外・来店履歴なし・ルール未一致・通常ランクを区別し、名称・色・根拠を同じ適用履歴から返す。スナップショット以前の履歴には既存フォールバック、不完全なスナップショットには422を適用する。計算済みのルール未一致を対象外や未計算と誤表示しない。
- 顧客詳細APIに`rf_rank_state`を追加し、型も一覧と共通化。DB・RF計算・保存済み履歴は変更しない。
- 初回取得失敗からの再読み込み、管理日時のAsia/Tokyo表示、RF色の安全なフォールバックを整備。基本情報・法人情報・備考・管理情報・権限に基づく編集導線を維持する。
- 予約履歴の`history_page`と顧客検索・RF内訳への`return_to`をURLへ保持。予約詳細の再読み込み後にも同じ顧客詳細へ戻れる。外部URL・別顧客への戻り先は採用しない。
- 予約結果表示は#223の共通処理を再利用し、退店済・通常キャンセル・無断キャンセルが受付状態の「予約確定」で隠れないことを検証する。

## ローカル検証

修正前にRailsの回帰テスト3件、フロント2件の失敗を確認した。

修正後の関連RSpec54件、関連フロントテスト37件（追加したRF分類2ケースを含む）が成功。RuboCop対象3ファイル、対象ESLint、Prettierと差分検査も成功した。

全RSpecは909件中908件成功、画像処理実行テスト1件が開発コンテナの`libvips.so.42`不足で失敗した。今回の変更による成功とは扱わず、libvipsを導入する独立CIで全体を再検証する。Rails実レスポンスから888件の型契約を再生成し、型検査は成功した。

初回の型検査では古い契約生成物と`.next/types`の「 2」付き生成ファイル4件が衝突した。前者を再生成し、後者のみ`/private/tmp/colette-160-generated-types-backup`へ移動して元の生成ファイルは保持した。アプリソースや既存のユーザー変更は削除していない。

開発サーバーの`/up`・ログイン画面・ログイン候補は200、未認証APIは401。既存ブラウザはセッション再認証待ちのため、ログイン後の画面受入済みとは扱わない。
