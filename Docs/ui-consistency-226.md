# 共通UIの棚卸しと役割（#226）

共通ヘッダーで現在地を表示する。本文の大きい画面名は繰り返さず、`PageHeading` の読み上げ用H1を残す。顧客名・RFルール名は業務上の識別情報として可視H1を維持する。通常画面のmainは共通レイアウトの1つだけとし、予約フォームやURL付きモーダル内へmainを重ねない。ログイン・障害画面の独立した見出しは維持する。

| 対象                                                    | 見出し・説明の扱い                                                                                 |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| ダッシュボード・顧客検索・予約一覧/カレンダー・各マスタ | 共通レイアウトが読み上げH1を補う。既存の機能見出し・検索条件・空/エラー表示を維持                  |
| RFランク表・客層変動・低下済み/予定・顧客内訳           | 本文の画面名を読み上げ用にする。同じ顧客の比較、予測条件、対象期間・基準日などの分析上の定義は残す |
| 顧客詳細・RFルール編集                                  | 顧客名/ルール名・ランク・状態/版数は残す。読込・失敗時にも代わりのH1を用意                         |
| パスワード変更                                          | 共通ヘッダーと読み上げH1で現在地を示し、入力条件と失敗案内を維持                                   |
| ログイン・独立した障害画面                              | 認証前/エラーの状況判断に必要な可視見出しと案内を維持                                              |

## 操作部品

- 画面遷移は`NavigationLink`（実体はNext Linkのアンカー）、状態変更は既存のButtonを使う。リンクをbuttonで包まない。角丸・配色・フォーカスは既存buttonVariantsとCSS変数を共用する。
- 主要・補助・危険操作の既存variantと、権限による可視性・無効状態を維持する。
- カード全体が遷移する既存リンクはカードの面を保つ。表内の人数・顧客名、戻る/詳細リンクは共通部品を使う。数値表の開閉はnative details/summaryの意味とマーカーを残す。
- タッチ端末の共通ボタン/リンク/開閉操作は44px以上の領域を確保する。PCでは既存の表の密度を維持する。

## #227へ渡す説明

削減したのは「RFルールの設定と計算履歴を管理します」「現在の顧客構成と前年同月からの変化を確認します」「条件とランク対応表を順番に設定します」など、機能見出しと重複する案内。操作手順として必要なら#227のオンデマンドヘルプに配置する。

取消・退店訂正、仮予約の同時確定、競合、権限、入力条件、RF計算/適用/復元、予測前提、基準日・集計定義はヘルプ実装前に削除しない。#228のグラフ・テーマ、#230の基本コードの横スクロール、#231のランク色はこの変更へ含めない。

## 検証

型/Lint/Vitestに加えて、実サービスE2Eで各画面のmain/H1の重複、現在地、リンクからの顧客詳細、予約登録・訂正・RF分析の既存導線を確認する。狭い画面・フォーカス・色の表示は実ブラウザと画像で確認し、DOMテストだけで完了とはしない。
