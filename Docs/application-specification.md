# Colette アプリ仕様の参照

## 目的と範囲

飲食店の予約受付、来店準備、顧客情報の共有を支援する。予約・顧客・席・担当者・基本コードを管理し、来店履歴からRF分析を行う。利用者は店舗スタッフ。

## 実装から確認した現在の仕様

- 認証はスタッフのセッションを使用。無操作4時間・ログインから絶対12時間で失効する。在籍状態・ログイン可否を確認する。役割コードはowner/operator/viewer。ownerは全操作、operatorは顧客・予約更新とマスタ閲覧、viewerは閲覧のみをAPIで強制する。
- 顧客は個人・法人。法人では法人名必須。手動の顧客ランクと計算されたRFランクは別概念。非表示・復帰と更新競合を扱う。
- 予約は顧客未選択でも登録できる。希望席種と実際の複数席割当は別。未割当予約を許可する。人数は正整数。
- 現在の予約開始時間は17時〜21時、終了は当日24時まで。これはReservationモデルの現在の設定であり、恒久固定値ではない。
- 完了とキャンセルは同時成立しない。キャンセルから復元するときも席の空きと予約競合を再検証する。同一顧客の有効予約の時間重複を禁止する。
- 席割当は有効性・定員・時間重複を検証する。作成・更新・復元と席マスタ更新を共通DBロックで直列化する。未完了・未キャンセルで終了予定が未来の予約を定員超過にする定員削減は拒否する。
- 予約作成APIはIdempotency-Keyを必須とし、同一スタッフ・同一キー・同一入力の再送は同じ予約を返す。異なる入力でのキー再利用は409。
- 担当者の編集・退職・復帰・ログイン可否・ロック解除はstaff_master.lock_versionを必須とし、古い更新は409で拒否する。
- RFの公開中・現在適用中・計算待ち/実行中ルールが使うランクと親カテゴリは停止できない。未使用の過去ランクを停止した場合、そのルールを適用/復元する前に有効へ戻す。
- 基本コードは用途ごとのカテゴリを持つ。表示ラベル・業務コード・DB識別子を区別する。
- RFは完了済み・未キャンセルの来店履歴、基準日、ルールの集計期間から計算する。未訪問・除外を区別する。計算と適用は別操作で、完了した計算だけを適用し、現在の適用結果との競合を確認する。
- 認証切れは同じ担当者による再認証で、画面上の編集中入力を保持して復帰する。更新リクエストは自動再送しない。本人のパスワード変更とownerによる再設定を用意し、変更時に既存セッションを失効して監査記録を残す。
- 更新フォームへの導線はowner/operator/viewerの権限に合わせて制御する。認可の最終判定はAPIが行う。
- 予約編集の409は、元の内容・自分の入力・最新内容を比較してから再編集する。確認済みの予約でも業務内容が変われば確認状態を解除する。
- RF低下予測は、予測基準日以降に来店しない仮定で初めて低下する日を表示する。予約の存在から将来来店を確定しない。適用中のRFランクと予測基準日に再計算したランクを区別する。
- RF分析・年月比較の人数から計算履歴を固定した顧客内訳、顧客詳細、予約履歴へ進める。顧客内訳の絞り込みとページ分割はDBで行う。
- RF月次計算は毎月1日03:00（Asia/Tokyo）に前月末基準で実行する本番定期ジョブ。重複・再試行と手動適用/復元の競合を検出し、計算失敗や競合時は現在の適用結果を維持する。配置先でscheduler/workerを起動する必要がある。
- ダッシュボードは店舗日付の本日の予約件数・未完了予定人数・未割当・未確認・完了・キャンセルと、時刻順の未完了予約を表示する。ダッシュボードは画面表示時と手動更新時に取得し、30秒間隔やフォーカス復帰時の再取得は行わない。ランク低下はダッシュボードに表示せず、専用画面で当月初日〜今日の一覧を表示する。顧客一覧はURLに検索条件を保持する。顧客・予約一覧は30秒ごとに更新し、フォーム編集中は自動更新を抑制する。
- 店舗時刻はconfig/application.rbで定義し、現在はAsia/Tokyo。

この文書は仕様の案内であり、実装の欠陥を正しい仕様として追認しない。文書・テスト・実装の矛盾は差分を示し、ユーザーが確定した仕様を優先する。業務上の意味が変わる場合は受入条件を確定してから変更する。
