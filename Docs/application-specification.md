# Colette アプリ仕様の参照

## 目的と範囲

飲食店の予約受付、来店準備、顧客情報の共有を支援する。予約・顧客・席・担当者・基本コードを管理し、来店履歴からRF分析を行う。利用者は店舗スタッフ。

## 実装から確認した現在の仕様

- 認証はスタッフのセッションを使用。在籍状態・ログイン可否を確認する。役割コードはowner/operator/viewer。全操作の権限表は未確定であり、viewerを完全な閲覧専用と実装済みと判断しない。
- 顧客は個人・法人。法人では法人名必須。手動の顧客ランクと計算されたRFランクは別概念。非表示・復帰と更新競合を扱う。
- 予約は顧客未選択でも登録できる。希望席種と実際の複数席割当は別。未割当予約を許可する。人数は正整数。
- 現在の予約開始時間は17時〜21時、終了は当日24時まで。これはReservationモデルの現在の設定であり、恒久固定値ではない。
- 完了とキャンセルは同時成立しない。キャンセルから復元するときも席の空きと予約競合を再検証する。同一顧客の有効予約の時間重複を禁止する。
- 席割当は有効性・定員・時間重複を検証する。並行リクエストの席競合防止は未完了の実装課題。
- 基本コードは用途ごとのカテゴリを持つ。表示ラベル・業務コード・DB識別子を区別する。
- RFは完了済み・未キャンセルの来店履歴、基準日、ルールの集計期間から計算する。未訪問・除外を区別する。計算と適用は別操作で、完了した計算だけを適用し、現在の適用結果との競合を確認する。
- 店舗時刻はconfig/application.rbで定義し、現在はAsia/Tokyo。

## 仕様の根拠と更新

README.mdが製品目的、backend/config/routes.rbがAPI経路、app/modelsとservicesが業務処理、serializersとfrontend/featuresの型がHTTP契約、request/service specsが期待動作の根拠。
この文書は仕様の案内であり、実装の欠陥を正しい仕様として追認しない。文書・テスト・実装の矛盾は差分を示し、ユーザーが確定した仕様を優先する。業務上の意味が変わる場合は受入条件を確定してから変更する。
