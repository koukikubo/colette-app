# ダッシュボードの受入確認（Issue #158）

## 対象と境界

調査基準はmain `51a2128`。既存実装の数値・日付境界・操作・異常時回復を確認する。#228のshadcn/uiグラフ置換・アクセントカラー設定、#231のRFカラー反映、#223の手動退店・来店結果訂正は含めない。

PR #205の最終headは`a101394`、マージコミット`e09f607`で、現行mainの祖先である。Issueの旧検証記録`fe24e62`だけを最終実装とは判断しない。#205以後のダッシュボード差分は、ユーザー指定による新規予約ボタンの削除とその回帰テスト。集計定義は維持されている。

## 確認する指標

| 指標                 | 現行の集計条件                                                                     |
| -------------------- | ---------------------------------------------------------------------------------- |
| 本日の予約件数       | Asia/Tokyoの本日を開始日とする未キャンセル予約。完了も含む                         |
| 来店予定人数         | 本日の未完了・未キャンセル予約の人数合計                                           |
| 未割当・未確認       | 本日の未完了・未キャンセル予約のうち割当なし／詳細確認日時なし                     |
| 完了・キャンセル     | 本日開始の予約を、それぞれの記録で区別                                             |
| 今月の予約           | 今月開始の未キャンセル予約。今後の予定も含む                                       |
| 年間累計来店         | 当年1月1日以降、予約開始・完了記録が現在以前の未キャンセル予約                     |
| 新規顧客・再来店比率 | 顧客を識別できる完了実績だけを使用。同日2回来店を別日の再来店にしない。分母0はnull |
| 常連・ご無沙汰       | 直近12か月4回来店、そのうち最終来店90日超。非表示顧客を接客候補に含めない          |
| 来店間隔             | 異なる4来店日以上から間隔中央値を求め、その1.5倍を超過して未再来店                 |
| RF分布               | 現在適用中の完了履歴に固定し、保存された名称・人数と顧客内訳への導線を維持         |

匿名の完了予約は来店件数へ含め、顧客比率には含めない。顧客が非表示でも実来店の件数から取り除かない。インサイトの全該当人数と最大5名の表示対象を区別する。

## 修正した不具合

本日集計が応答待ちになると更新ボタンが無効になり、別取得の分析APIが失敗しても手動で再試行できなかった。更新ボタンを取得中でも操作可能にし、既存`useApiRead`による中断・旧応答の破棄を利用する。定期更新・フォーカス復帰取得は追加しない。

変更前に失敗するVitestで応答待ちと分析失敗を同時に再現し、再試行後の成功と旧応答の不採用を確認する。チャート・配色・API・集計SQL・DB構造は変更しない。

## 検証と証跡

- Request Spec：UTCでは前年でもJSTで年・月・本日を切り替える境界、キャンセル・未完了の除外、同日来店、90日/91日、中央値1.5倍、非表示、全人数と表示上限、viewerの閲覧。
- Vitest：応答待ちと失敗からの再試行、古い応答の破棄、owner/operator/viewerの空状態、分母0、RF履歴なし、日付付き予約導線、両APIの取得頻度。
- 実サービスE2E：空の専用DB→画面で予約・完了→実績APIとの数値照合、通信切断から手動回復、3/6/12か月の数値表との一致、PC/820px/390px、キーボードでの日付付き予約遷移。
- RSpec実レスポンスを既存フロント型へ照合し、型・Lint・整形・ビルドと必要な全体回帰を実行する。

ローカルの全体RSpec 880件・Vitest 511件が成功。実Rails由来819件の型契約照合、ESLint・RuboCop・整形確認も成功した。

E2Eは通常の開発DBでは実行せず、GitHub Actionsの専用PostgreSQLとRails/Nextを使用する。実行結果・レビュー・最終受入はPRとIssue #158へ記録する。グラフ表示部品の作り替えは#228で一度だけ行い、今回追加した数値検証を回帰に使う。
