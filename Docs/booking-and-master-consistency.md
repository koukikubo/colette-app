# 予約・マスタ整合性の改修（2026-11-13）

対象は再調査で再現した4点。ブランチ: `fix/booking-and-master-consistency`。

## 予約作成の再送

`POST /api/v1/reservations` は `Idempotency-Key` ヘッダーを必須とする。16〜128文字の英数字・ハイフン・アンダースコア。フロントは作成操作ごとにUUIDを発行し、Next proxyもそのままRailsへ渡す。

同じスタッフ・同じキー・同じ許可済み入力なら、新規作成せず同じ予約を201で返す。返す予約は現在の状態。同じキーで別入力を送ると409 (`code=idempotency_conflict`)。キー未指定・不正は共通JSONの400。入力エラー時は予約とキー記録の両方を保存しない。別キーなら同内容の正当な別予約も作成可能。

予約とキーの記録は一つのトランザクションと既存の予約共通ロックで保存し、同時再送でも作成を1件にする。DBにもスタッフとキーの一意制約を追加。キーと入力のSHA256のみを記録し、入力本文の個人情報を別テーブルへ複製しない。

画面は通信切断/5xxの場合、フォーム内で前回のキー・本文を保持する。入力を変えて別予約として再送することを止め、「前回の内容で再試行」を提供する。成功後は再送を止め、予約一覧へ移動する。フォームを破棄・再読込して新しい操作を始める際は、元のキーを保持できないため先に予約一覧で結果を確認する。予約の全内容をブラウザ永続ストレージに保存する実装は追加していない。

## 席の定員削減

席更新は予約作成・編集・キャンセル復元と同じDBトランザクションロックを使う。未完了・未キャンセルで終了予定時刻が未来の予約について、削減後の複数席の合計定員が予約人数を満たさなくなる場合は422。エラーに影響する予約IDを示す。

複数席の合計が足りる場合、定員増加、過去・完了・キャンセル済み予約だけの場合は変更できる。過去の席名・定員を新たにスナップショット化する機能は今回の対象外。

## 使用中RFランクの無効化

公開中のルール、現在適用中の計算に対応するルール、pending/processingの計算が使う未訪問ランクと対応表のランクを保護する。ランク単体だけでなく親カテゴリの無効化も422で拒否する。使っていないランクや、現在使っていないアーカイブルールのみが参照するランクは無効化可能。

RFの公開・更新・アーカイブ・計算開始・適用・復元とランク停止を共通のDBロックで直列化する。停止と公開が同時でも無効な公開ルールを作らない。過去の未使用ルールが停止済みランクを参照する場合、適用・復元前にも有効性を確認する。

計算開始ではルール検証とpending履歴の作成を同じトランザクションにし、履歴をコミットしてから別DBのJobを登録する。

旧データに停止済みランクがある場合の分析スナップショットの検査は継続する。そのテスト準備に限り `update_columns` で旧状態を作り、通常の更新APIで停止できることを期待しない。

## 担当者の更新競合

StaffMasterへ `lock_version`（既存行は0）を追加し、一覧・詳細・変更結果のJSONへ返す。以下の変更には、取得時の `staff_master.lock_version` を必須とする。

- 基本情報の編集
- 退職、復帰
- ログイン可否の変更、ログイン失敗回数の解除

未指定・不正な版は400、古い版は409。認証情報の変更も担当者の版を進め、認証情報の保存が失敗したら版の更新もロールバックする。ログイン成功/失敗そのものによるスタッフ情報更新は、この管理画面用の版を進めない。

フロントの型・API・各ダイアログへ版を通し、編集中に一覧データが更新されても入力開始時の版を自動で新しくしない。409ではAPIの案内を表示し入力を保持する。一覧には更新ボタンを追加。最後のowner保護と権限制御は維持する。

## 導入

追加のマイグレーションは2つ。予約再送記録テーブル、担当者の版番号列と非負制約を追加する。既存顧客・予約・担当者を削除する処理やseedはない。

```sh
docker exec colette_backend bundle exec rails db:migrate
docker exec -e RAILS_ENV=test colette_backend bundle exec rails db:migrate
```

ローカルの開発DB・専用test DBには上記マイグレーションを適用済み。本番DBには未適用。API契約に必須項目が増えるため、配置時はDB変更後にRailsとNextを揃えて更新し、独自のAPI呼び出し元にもキー/版番号を渡すこと。前回ビルドしたイメージには今回の変更は含まれないため、配置時には再ビルドする。
